ProjetVet documentation

Human-readable documentation for the implemented features of the mod_projetvet Moodle activity — written for the people who use or maintain the module (managers, tutors, students, site administrators), to explain how the module works and what to expect from each feature.

Each document is a Markdown file (.md). Browsers display it as plain text — it is written to be readable as is. README.md is the source of truth for this folder (it also contains the mapping to the formal OpenSpec specifications); this page is its HTML entry point.

The module in one page

ProjetVet manages the follow-up of student projects by tutors. Three roles matter:

  • Students work through the stages of a project (eligibility, activity, report…). At the report stage (“Bilan du projet”) they must complete a set of mandatory fields, including at least two confirmed competencies. They can archive the projects already validated under the previous CPP system, and delete their own projects.
  • Tutors (tuteurs) follow one or more students per activity. Each tutor has, per activity, an availability status, a capacity level (12/8/5 students) and an A1 acceptance flag — all checked together, in one place, before any new assignment. Tutors can broadcast a message to the students they follow, and their temporary substitute follow-up is clearly distinguished from their principal follow-up.
  • Managers (gestionnaires) assign and re-assign students to tutors (manually, in bulk, or via CSV import), can optionally notify the people concerned when an assignment changes, appoint temporary substitute tutors per student, and review the students' archive of previously validated (CPP) projects.

All user-facing notifications go through a single queued delivery path that respects each recipient's language and Moodle messaging preferences.
